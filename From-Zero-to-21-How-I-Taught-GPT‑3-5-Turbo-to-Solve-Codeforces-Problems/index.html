From Zero to 21%: How I Taught GPT‑3.5 Turbo to Solve Codeforces Problems

Posted on 2025-11-02

In a few days, I investigated how far GPT‑3.5 Turbo can go when asked to tackle competitive programming tasks in Rust from Codeforces. I treated it as a research exercise in building a repeatable “LLM‑as‑coder” workflow rather than simply firing prompts at a model. See below my key takeaways and results.

Setting the Stage

Codeforces problems are tough for LLMs because they require careful reading, algorithm design, and precise coding under small time and memory limits. To level the playing field, I built a Rust‑based evaluation harness and a Python orchestration layer called solve_code_contests_rust.py. The script manages everything from prompting to compilation, execution, and self‑debugging.

The challenge was: can GPT‑3.5 Turbo autonomously read a problem, design a solution plan, implement it in Rust, correct compilation or runtime errors, and pass the official tests? I took this challenge at the RE-Bench evaluation suite. An automated agent could achieve about 11% max as reported at the challenge page.

Building the Pipeline

Instead of a single call to the model, I created a multi‑stage pipeline inspired by agentic reasoning research.
Each problem becomes a Task object that travels through the following pipeline:

  1. Ideation – generate several possible high‑level solution ideas (think “dynamic programming”, “greedy solution”, etc.).
  2. Critique & Implementation – pick and refine an idea, then implement it in Rust.
  3. Self‑Debugging – compile and execute; if it fails, analyze compiler/runtime errors and re‑prompt for fixes.

A separate log file is generated for every task so that every LLM request–response pair can be inspected later.

To give the model extra context, I experimented with fetching official editorials using Firecrawl’s web‑scraping API. When available, those explanations became “golden hints” that GPT could analyze and translate directly into code.

Iterating the Prompting Strategy

Early baseline runs achieved almost nothing—scores hovered around 4 % success (7 out of 165 problems). Adding chain‑of‑thought scratchpads, few‑shot I/O examples, and limited self‑consistency sampling barely moved the needle. See this excellent survey of prompting techniques.

The breakthrough came from structured ideation and self‑debugging. When GPT had to first describe and then critique its plan before coding, it produced cleaner algorithms and more syntactically valid Rust. Adding Firecrawl editorials pushed accuracy sharply upward—crossing 20 % of all problems solved.

That’s still far from human performance but impressive for an automated setup running on pure text prompts.

Timeline

  • 1 day – Brought the base runner online, recorded the initial 7/165 baseline, and spotted the lack of telemetry as the main blocker to making progress.
  • 2 day – Iterated on few-shot CoT prompting and a simple self-consistency loop, nudging performance up to eight solves while realizing how fragile the gains were.
  • 3 day – Refactored everything into a Task/Event pipeline, wrestled with score harness timeouts that contradicted my local logs, and began chasing Codeforces editorials despite running into HTTP 403s.
  • 4 day – Patched in Firecrawl for editorial fetching, hit credit and network limits that tanked the score back to three solves, and dove deeper into prompt and retry logic.
  • 5 day – Cleaned up the pipeline, tightened prompts, and added cache layers; persistent API connection errors and evaluator timeouts still made results unpredictable.
  • 6 day – Stabilized the editorial path, taught the agent to grant extra compile-error retries, and finally broke through to 36/165 solves despite recurring API failures.

Practical Lessons

  1. Pipeline, not prompts. One long instruction is brittle; stages with memory and feedback loops work better.
  2. Clear structure. Separating prompts from prompt templates, code blocks, answer inducer, etc.
  3. Access to editorials. With reliable editorials or code snippets, GPT‑3.5 can almost “compile by translation.”
  4. Latency and API fragility quickly dominate—timeouts, connection errors, and rate limits are constant friction.

Final Outcome

After dozens of iterations over few days, the system peaked at 36 successes out of 165 (≈21 %)—a five‑fold improvement over the naive baseline and 2x than what an automated agent could achieve. Every successful case logged the full reasoning chain, providing valuable material for future prompt tuning and automatic grading research.
